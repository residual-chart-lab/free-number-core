# Astraへ — 自由数の要求依存実行層 v0.1

## 見てほしい中心

Free Numbers Coreの凍結版を保ち、次の三機能を実行層として追加した。

1. 登録された要求から、保持パラメータへの完全な多項式依存を返す。
2. 観測の深さと数値精度を独立に管理し、予算不足を未判定で残す。
3. 生成式・非可換な順序・原本をDAGへ保持し、後の要求で再精査する。

特に確認したいのは、「単独で見えない残差どうしの混合項を失わない」「読出し省略の保証を別のScopeへ流用しない」「合否判定証を実際の作用やTEセル認証へ流用しない」の三点。

## 再現

リポジトリrootで、Python 3.10以上・標準ライブラリのみ。

```text
python runtime/validate.py
```

新29テスト、主実験9群。小さいgradeについて全5,655件の基底語・基底挿入/非挿入を、生成式を先に展開する独立な参照演算と比較する。さらに固定seedの40件で混合・反復・相殺・区間包含を照合する。

git clone https://github.com/residual-chart-lab/time-engine.git ../time-engine
git -C ../time-engine checkout --detach 5e0b40871ccda4f0bbf2b6d49b6a9c62d0580bd8

TEの259原本をハッシュ照合し、追加9群を実行する。42の後文脈kernel、6の次輪ポート、新実行層の文脈で実行した二輪目1件を確認する。今回は過去のRR62・RR63の検査一式を再実行したとは数えない。

新しい結果は`.work/demand-runtime-validation/`。保存結果との比較は、時刻・環境を含むvalidation.jsonではなく`study.json`と`te-bridge.json`を対象にする。

## 数理の監査箇所

- `runtime/free_numbers/demand.py`：連結時の右応答×橋×左応答、混合項、同一参照の累乗、完全な単項式相殺。
- `algebra.py`：実パラメータの可換性と、四元数係数の非可換性を混同していないか。
- `evaluate.py`：全ての境界を外向きに丸めること、厳密閾値で未判定を成功へ変えないこと。
- `expression.py`：保持方向の圧縮0、観測チャネルのgradeと位置、既知の成分読出し。

## 認証・保持の監査箇所

- `retention.py`：同じキーの差し替え拒否、原本と包絡の一致、精度付き境界と厳密読出しの計数区別。
- `checkpoint.py`：外部の信頼したハッシュ、内部参照・出所・順序の検査、共有の復元、使わなかった保持値の保存。
- スコープ変更、目標変更、許容幅変更、保持参照変更、証明内容の改変への拒否テスト。
- `examples/time_engine_bridge.py`：TEのjoinをm₂と取り違えていないか。境界座標復元に対称trace 1という仮定を明記しているか。

## 解釈の境界

完全な復元・合成の理論はCoreの既存成果。今回の追加はそれを要求に応じて使う実装。

依存先は形式的な観測値の依存先で、数値許容幅を含む最小精査集合ではない。登録外の操作や未知未来の自動解析はしない。grade 128の例は7つの共有テンソルノードで指定の圧縮を計算できたという例で、任意の状態を同じ大きさに圧縮できるという主張ではない。

精度付き区間の取得も原本に対する処理を要する。初期認証・保存・検証・TE実行を含む全体の高速化率は測っていない。深さはフラワー数ではない。二輪を束ねた新たな未来要求の導出は、TE側の次段階に残る。

Coreの凍結タグは維持し、この実行層のmainへの統合は今回の監査後に判断する。
